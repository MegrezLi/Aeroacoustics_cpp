# 五项性能优化：实现、验证和复现

本轮先合入 `ffc85ed` 的四项正确性修复，再优化内存和重复计算。BPM 文献教程及其公式显示修复也保留在同一分支。优化基线的模型实现是 `ffc85ed`；不要直接与尚未包含统计修复的旧主分支比较 LAeq 等结果。

## 改了什么

### 1. TNO 缓冲区按需分配

`TnoWorkspace` 默认只创建空向量，首次准备有效的 TNO 边界层剖面时才分配积分数组。BPM、Howe 及关闭声源的路径不再承担这些数组的初始化成本。首次分配成功后，后续 TNO 调用复用同一份存储；双侧摩阻系数均不激活积分时也不提前分配。

单截面返回值接口仍会分配结果谱。重复参数扫描应使用 `AcousticWorkspace`；其预热后的固定尺寸求值继续保持无新增堆分配。没有通过共享全局可变缓冲区来提高性能。

源码：[tno.cpp](../src/acoustics/tno.cpp)、[source_models.hpp](../src/acoustics/source_models.hpp)。

### 2. 完整观察点块与尾块各自复用

原实现每次将嵌套快照缩小到尾块大小，销毁了其余观察点内层的频谱向量。下一帧再扩回完整块，就必须重新分配。

现在完整块与不足一块的尾块各有缓冲区。回调收到的快照尺寸仍然等于真实观察点数，索引、顺序和借用生命周期保持原样。完整快照接口仍返回所有观察点；复制工作区会复制各自的数据。

这是用少量常驻内存换掉反复分配：块大小为 B 且不能整除观察点数时，最多同时保存 B 个完整块位置和 B−1 个尾块位置。默认 B=1 时没有额外尾块缓存。修改块大小或节点数时仍允许分配；这里只保证固定配置预热后的复用。

源码：[workspace.cpp](../src/acoustics/workspace.cpp)。

### 3. 连续历史存储和不分配内存的插值

宽带 `ArrivalHistory` 将时间信息与频谱分别放进两个连续数组，避免每个节点、前后缘、观察点、时间样本各有一个独立频谱向量。追加过程复用声能暂存区。CSV 汇总直接把插值频谱累加到现有频带数组中。

游标由一次查询过程持有，递增时间可以沿区间向前走，倒退查询会重新定位。公开的 `ArrivalSeries::at()` 仍保留，新增 `at_into()` 让音调及风速查询也复用输出缓冲区。历史对象没有隐藏的可变查询状态，复制和检查点保持独立。

统计仍使用所有源到达时间、风速节点和窗口端点的并集。没有改变 ReceiverDT、AM 采样、音调修正、插值公式或接收时延；也没有把前后缘路径提前合并。`MaxValues` 保留原来的保守计数和拒绝行为。

连续数组按容量增长，扩容仍会复制历史；累计申请字节不一定减少，也没有承诺进程峰值内存下降。本轮解决的是大量小对象分配及查询时的复制，尚未实现无限时长流式存储。

源码：[arrival_history.hpp](../src/turbine/analysis/arrival_history.hpp)、[metrics.cpp](../src/turbine/analysis/metrics.cpp)、[statistics.cpp](../src/turbine/analysis/statistics.cpp)。

### 4. 传播计算共享相同的前后缘路径

同一节点的六类尾缘声源共用尾缘位置，入流声源使用前缘位置。现在按两条路径准备距离、反射点及反射系数，再逐频带计算屏障衍射、相位和带内相干系数，最后应用到对应声源。

各机制仍分别进行直达与镜像声的相干叠加，机制之间的合成方式没有改变。路径长度和相位不会跨节点、观察点或时间缓存；共享的传播对象仍然可以被多个独立求解器只读使用。

源码：[outdoor.cpp](../src/propagation/outdoor.cpp)。

### 5. TI 方法 2 使用滚动中心矩

环形窗口替换一个样本时，更新均值与中心平方和。每个窗口长度重新完整计算一次，首次替换及中心平方和出现负值时也重新计算，以限制浮点漂移。滚动量使用 `long double`，避免直接相减两个大的原始二阶矩。

保留了原来的区域编号、样本替换下标、窗口填满前输出 0、以及声学采样读取更新前 TI 的顺序。方法 1 的计算公式不变。每次完整重算仍为 O(N)，摊销到 N 次更新后，每次更新成本为 O(1)。

TI 方法 2 不保证逐位一致；新增测试覆盖单元素和长窗口、常量、微小扰动、周期来流、阶跃后的恒定来流及复制状态。公开 `TurbulenceState` 增加成员，使用 C++ 库的调用方应重新编译链接。

源码：[driver.cpp](../src/acoustics/driver.cpp)、[aeroacoustics.hpp](../include/aeroacoustics.hpp)。

## 如何验证

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DAEROACOUSTICS_BUILD_TESTS=ON
cmake --build build -j 4
./build/optimization_probe
./build/review_regression_probe build/review-regression
./build/aeroacoustics_bpm1989 build/bpm1989.csv --check
```

Windows/MinGW 先设置编译器路径，配置时加 `-G "MinGW Makefiles"`，程序名加 `.exe`；Visual Studio 构建及运行需选择 Release。

本轮还运行原有的声学工作区、工程传播、统计、仿真和性能 API 检查；执行 Fortran 声学对照、8/9 m/s 完整整机对照，以及表格边界层和短 TNO 工况与旧版的逐字节比较。详细结果见 [validation-optimization-five.json](validation-optimization-five.json)。

## 如何重做性能比较

`tests/optimization_benchmark.cpp` 是同一个基准入口，分别使用旧版头文件/静态库和新版头文件/静态库编译，避免混用改变了布局的 C++ 类型。两边应使用相同编译器、Release 选项、MKL 设置及机器环境。

```sh
python tests/benchmark_optimizations.py /baseline/optimization_benchmark /candidate/optimization_benchmark build/paired-benchmark --rounds 5
```

脚本先预热，再交替运行五轮，报告中位数、new/new[] 次数、累计申请字节和数值校验和。基准生成的接收点历史、统计、风速分箱和 AM 文件必须逐字节一致。程序哈希和原始五轮数据保存在报告中；性能记录不要与不同基线的历史文档混用。

基准包括 1000 次 BPM 单截面调用、固定尺寸工作区、66 节点/17 观察点/块大小 4、两屏障阻抗地面传播、1000 样本窗口的 TI 方法 2，以及 8 观察点/12 节点/201 时刻的接收点统计。局部基准收益不代表整机得到相同幅度的提速。

## 2026-10-12 本机实测

Windows、GCC 16.2.0、Release 普通后端，预热后交替运行五轮，取中位数。

| 工况 | 优化前 / ms | 优化后 / ms | 耗时减少 |
| --- | ---: | ---: | ---: |
| BPM 单截面，1000 次 | 89.412 | 11.835 | 86.8% |
| 已复用 BPM 工作区，1000 次 | 11.269 | 10.926 | 3.0% |
| 17 观察点、块大小 4，30 次 | 56.501 | 50.628 | 10.4% |
| 两屏障及阻抗地面传播，10000 次 | 557.198 | 244.864 | 56.1% |
| TI 方法 2，窗口 1000、更新 100000 次 | 2207.889 | 3.767 | 99.8% |
| 统计历史追加，8 观察点、201 时刻 | 120.300 | 117.290 | 2.5% |
| 统计与 CSV 输出，1 次 | 126.130 | 115.728 | 8.2% |

已复用工作区和历史追加的计时变化较小，不据此宣称稳定提速。更明确的收益是分配次数：1000 次 BPM 单截面由 26000 降至 12000；30 次尾块测试由 41670 降至 0；统计追加由 42000 降至 5136；统计输出由 111642 降至 36562。

统计追加的累计申请量从约 17.1 MB 增至 29.3 MB，原因是连续数组扩容；这不是峰值 RSS。单截面的累计申请量从约 156.5 MB 降至 3.26 MB。原始字节数保存在 JSON 中。

16 组本地验证通过。Fortran 对照覆盖 56576 个声学值，最大差值约 4.55×10⁻¹³ dB。8/9 m/s 整机、表格边界层以及短 TNO 工况的数值文件与优化前逐字节一致；性能基准产生的接收点统计文件也逐字节一致。TI 方法 2 新增测试的最大绝对差异约 2.59×10⁻¹¹。
